8. 延迟 / 成本 / 规模 — zerver/lib/topic_title_improver.py

作业要求你必须讲清这三点。对着下面 5 条说：

  1. 能不调就不调：should_call_llm — 少于 3 条，或标题词还在最近消息里，返回 skipped_llm: true。
  2. Prompt 很小：最多 20 条 × 约 280 字符，max_tokens=180。
  3. 缓存 45 秒：key = (stream_id, last_message_id, topic)。
  4. 只打发送者：没有 Tornado 广播，不会消息风暴。
  5. 失败不影响发送：前端 error() {} 空处理；解析失败 drifted: false。
MIN_MESSAGES_FOR_DRIFT = 3
MAX_TOPIC_MESSAGES = 20
CACHE_TTL_SECONDS = 45
GENERIC_TITLES = {"hi", "question", "help", ...}

if not llm_is_configured():
    suggested = _heuristic_title(...)  # 没 key 的保底：从最长消息抽一句

api.key 在仓库根目录且 gitignore。优先级：环境变量 → 文件 → Zulip 的 topic_summarization_api_key。换 OpenAI / Gemini 不用改业务代码。

风险（作业 reflection，约 1 分钟）

  1. 幻觉：摘要可能编，所以每条配 Jump 链接让用户核对。
  2. 改标题危险：全 realm 可见，所以绝不自动 rename。
  3. 隐私：未读正文会发给第三方 LLM。
  4. 规模：现在是请求时同步调用。生产应改成队列 + 已有的 AI 用量统计。
  5. Prompt injection：消息里可能写「忽略指令」；生产要隔离 prompt、锁输出 JSON。
