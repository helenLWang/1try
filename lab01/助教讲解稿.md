## 2. 什么是 topic？什么是 offset？断线为什么不会丢消息？

Kafka 把数据存成**按 topic 命名的追加日志**。Topic 就是这条流的名字，producer 往这个名字写，consumer 按这个名字读。我的实验 topic 是 `lab01-helenlwang`，里面只有 1 个 partition。

Partition 内部每条消息有一个单调递增的整数 **offset**，相当于行号。本次我写入了 20 条，Kafka 分配的 offset 是 **0 到 19**。下一条将被写成 offset 20，这个「下一条的位置」叫 high watermark。

Consumer 属于一个 **consumer group**。它每读一批可以 **commit** 当前 offset。如果进程断了：

1. 消息还在 broker 的日志里（在保留期内不会因为有人读过就删掉）。
2. 重连后 group 从**上次提交的 offset 之后**继续，所以既不会凭空丢已提交之后的数据，也不会默认把已经处理过的再处理一遍。
3. 如果我想故意重放，就换一个 `group_id`，或调用 `seek()`，或在 kcat 里写 `-o 某个数字`。

## 3. `auto_offset_reset` 的取舍

这个参数**不是**「从哪里开始读」的通用旋钮。它只在下面同时成立时生效：

- 这个 consumer group 对这个 partition **还没有**有效的 committed offset（新 group，或 offset 已被删掉）。

而且它只能选日志的**两端**：

| 值 | 行为 | 适合 |
| --- | --- | --- |
| `earliest` | 从还保留的最老 offset 读（我这里是 0） | 要历史、要重放、本 lab 验证写入 |
| `latest` | 跳到水位线，只等新消息 | 实时任务，不在乎停机期间漏掉的数据 |
| `none` | 没有 committed offset 就报错 | 调试；避免静默跳到某一端 |

权衡：`earliest` 可能重放很久以前的数据（重复处理 / 启动变慢）；`latest` 会在故障期间丢消息；`none` 最安全但要求你自己管理 offset。

我的 consumer 用 `earliest`，所以 20 条历史全部读回，并写进 `kafka_log.csv`。

## 4. 三个 seek：哪个 `auto_offset_reset` 自己能到？哪个必须 seek？

我先问 broker 有效范围：

```text
beginning_offsets = 0
end_offsets       = 20    # 下一条将要写入的位置
readable          = 0 .. 19
```

然后 `seek()` 到三个点，每个点读 2 条：

| 起点 | 读到 | `auto_offset_reset` 能否自己到 |
| --- | --- | --- |
| **0**（开头） | offset 0, 1 | 能。这就是 `earliest` |
| **10**（中点） | offset 10, 11 | **不能**。两端策略到不了中间。必须 `seek()` |
| **18**（水位线前 2 条） | offset 18, 19 | **不能**。`latest` 会到 20（现在是空的），不会到 18。这就是「重放最后 2 条」，真实系统里常用 |

所以助教问 “which needed seek”：中间的 10，以及「最后 2 条」的 18，都需要 `seek()`。只有真正的开头（0）和真正的末尾（20，还没有消息）是 `auto_offset_reset` 能独立选的。

## 5. kcat 我跑了什么？offset 对得上吗？

```bash
kcat -b localhost:9092 -t lab01-helenlwang -C -o beginning -c 5 -e -f "%o: %s\n"
```

输出从 `0:` 开始，内容和 Python consumer 的 offset 0–4 一致。

```bash
kcat -b localhost:9092 -t lab01-helenlwang -C -o 8 -c 5 -e -f "%o: %s\n"
```

输出从 `8:` 开始（Pittsburgh, 64），正好是 Python 打出来的 offset 8。这证明 CLI 的绝对 offset 和 Python API 是同一套日志地址。

`-o` 还可以：`beginning` / `end` / `-5`（倒数 5 条）/ `s@<毫秒时间戳>`。
